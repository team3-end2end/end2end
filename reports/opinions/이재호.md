# 본인 의견 — 이재호 (보고서 자동 생성 시스템)

> 아래 「사실 정리」는 확인용입니다. 「느낀 점」·「개선하고 싶은 부분」은 초안이니 본인 문장으로 고쳐 쓰세요.

## 사실 정리 — 내가 만든 것

`reporting/` 패키지 전체와 테스트를 담당했다.

- **단계별 입력 계약 정의** (`reporting/schemas/stage-v1.schema.json`): 파이프라인 5단계(run / eda / preprocessing / model / evaluation)가 각각 어떤 값을 어떤 형식으로 넘겨야 하는지 JSON Schema로 먼저 정의했다.
- **2중 검증** (`reporting/contracts.py`): 스키마가 키·타입을 검사한 뒤, 스키마로 표현할 수 없는 규칙을 코드로 추가 검증한다 — 클래스 비율 합이 1인지, 필터 단계의 행 수가 앞뒤로 연결되는지, 혼동행렬 행 합이 클래스별 support와 같은지 등.
- **보고서 생성기** (`reporting/generator.py`, Jinja2): 같은 데이터로 팀 내부용 `report.md`와 비개발자용 `report.html` 두 벌을 만든다. HTML은 이미지를 base64로 내장해 파일 하나만 열면 되게 했고, 외부 스크립트·폰트를 쓰지 않는다.
- **최신성 검사** (`--check`): 생성된 보고서가 입력 JSON과 어긋나면 오류를 낸다. 누군가 `report.md`를 손으로 고치면 즉시 걸린다.
- **테스트 24개** (`tests/`): 잘못된 입력(빈 값·형식 오류·모순된 수치)을 넣었을 때 조용히 통과하지 않고 거부되는지 확인한다.

## 핵심 결정과 근거

**"보고서는 계산된 수치만 정리하고, 해석과 판단은 사람이 한다"** 는 경계를 처음부터 명시하고 그대로 지켰다. 그래서 템플릿에는 해석을 넣는 자리가 없고, 자동 생성물(`report.md`)과 사람이 쓴 최종본(`reports/final_report.md`)이 분리돼 있다.

또 하나는 **계약을 먼저 정의한 것**이다. 앞단 작업이 끝나기 전에 빈 보고서와 예시 데이터로 구조를 먼저 만들어 두어서, 각 단계가 완료될 때마다 JSON만 채우면 문서가 완성되는 구조가 됐다.

## 느낀 점 (초안 — 본인 문장으로 고쳐 쓸 것)

검증을 촘촘하게 짜둔 것이 실제로 값을 했다. 팀에서 실측값을 연결할 때 형식이 어긋난 입력이 바로 거부됐고, 덕분에 잘못된 숫자가 보고서에 실리는 일을 막을 수 있었다. "조용히 틀리느니 시끄럽게 멈춘다"는 원칙이 왜 필요한지를 만든 쪽에서 확인한 셈이다.

한편 예상하지 못한 문제도 겪었다. 날짜 형식 검증 테스트가 다른 팀원 컴퓨터에서만 실패했는데, 원인은 jsonschema의 날짜 검사가 보조 라이브러리 유무에 따라 켜지고 꺼지면서 에러 메시지가 달라진 것이었다. 잘못된 날짜는 양쪽 환경 모두에서 정상적으로 거부됐지만, 테스트가 "에러가 났는가"가 아니라 "에러 메시지가 무엇인가"까지 검사한 탓이었다. **테스트는 동작을 검증해야지 특정 환경의 문구에 의존하면 안 된다**는 것을 배웠다.

## 개선하고 싶은 부분 (초안)

- **파이프라인 → 보고서 연결이 아직 수동이다.** 지금은 학습이 끝나면 사람이 JSON을 채운다. 여기에 손으로 숫자를 옮길 여지가 남아 있어, 원래 목표였던 "자동 생성"이 절반만 달성된 상태다. 평가 함수가 클래스별 지표를 반환해 `evaluation.json`을 직접 쓰도록 만드는 것이 다음 과제다.
- **검증만 하고 노출하지 않던 값이 있었다.** `generated_at`(실행 시각)을 시간대까지 강제해 검증했지만 정작 보고서에 출력하지 않아, 나중에 템플릿에 추가했다. 검증 항목을 정할 때 "이 값을 누가 어디서 보는가"까지 같이 설계했어야 했다.
- **테스트가 `reporting/`에만 있다.** 학습 파이프라인에는 테스트가 없다. 다만 커버리지 숫자가 곧 품질은 아니라고 생각한다 — 커버리지는 "실행은 해봤다"는 뜻이지 "버그가 없다"는 증명이 아니다.

## 생각할 거리 (답해보면 본인 목소리가 나옵니다)

- 스키마를 먼저 정의하는 방식이 실제 협업에서 도움이 됐나, 아니면 앞단이 안 끝난 상태에서 형식을 정하느라 어려웠나?
- 검증을 어디까지 엄격하게 할지 정할 때 기준이 있었나? 너무 엄격해서 불편했던 규칙은 없었나?
- 다시 만든다면 `report.md`와 `report.html` 두 벌을 유지할 것인가, 하나로 줄일 것인가?
