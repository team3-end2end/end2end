# 본인 의견 — 장소영 (ML 파이프라인)

> 아래 「사실 정리」는 확인용입니다. 「느낀 점」·「개선하고 싶은 부분」은 초안이니 본인 문장으로 고쳐 쓰세요.

## 사실 정리 — 내가 만든 것

`pipeline.py`와 `config.py`, 즉 학습 파이프라인 전체를 담당했다.

- **sklearn Pipeline 객체 구성**: `GeoEncoder → SimpleImputer → StandardScaler → 모델` 4단계를 하나의 Pipeline으로 묶었다. 전처리가 모델과 한 덩어리라, 저장한 모델 파일 하나만 있으면 원본 데이터를 그대로 넣어 예측할 수 있다.
- **누수 방지 타깃 인코딩** (`GeoEncoder`): 승차/하차 지역 ID를 결제수단 비율로 바꾸는 인코더를 직접 만들었다. Pipeline 안에 넣었기 때문에 교차검증에서 **fold마다 학습 데이터로만 인코딩이 계산**된다 — 밖에서 미리 인코딩했다면 검증 데이터 정보가 새어 들어갔을 것이다.
- **Optuna 자동 탐색**: 모델 종류(xgboost / hist_gbm / logistic)와 하이퍼파라미터를 함께 탐색하도록 100 trial을 돌렸다. 3-fold 교차검증 macro F1이 기준.
- **불균형 대응**: 현금이 전체의 9%뿐이라 `class_weight="balanced"`를 적용했다. XGBoost는 이 옵션이 없어서 `sample_weight`로 대체했다.
- **재현성 고정**: `config.py`의 `SEED = 42`를 데이터 분할·교차검증·Optuna 샘플러·모든 모델에 일관되게 넣었다.
- **설정 분리**: 바꿀 만한 값(모델 목록, trial 수, 표본 크기, 가중치 사용 여부)을 `config.py`에 모으고, 각 항목에 "언제 이 값을 바꾸는가"를 주석으로 달았다.

## 핵심 결정과 근거

**탐색은 표본으로, 최종 학습은 전체로.** 389만 행 전체로 100 trial을 돌리면 시간이 감당되지 않아, 튜닝은 50만 행 표본으로 하고 최적 설정을 찾은 뒤 전체 데이터로 재학습했다. 전체 실행 시간은 약 40분.

**주 지표를 accuracy가 아니라 macro F1로 잡은 것**도 의도적이었다. 카드가 68%라 전부 카드라고 찍어도 정확도 68%가 나오기 때문에, 소수 클래스를 무시하는 모델이 좋아 보이는 것을 막아야 했다.

## 결과 요약

| 모델 | 탐색 trial | CV macro F1 |
|---|---:|---:|
| xgboost | 78 | 0.6686 |
| hist_gbm | 11 | 0.6335 |
| logistic | 11 | 0.5028 |

최종 선택은 XGBoost, **Test macro F1 0.6688 / accuracy 0.7428**.

## 느낀 점 (초안 — 본인 문장으로 고쳐 쓸 것)

가장 인상적이었던 건 **CV 점수(0.6686)와 Test 점수(0.6688)가 0.0002 차이밖에 안 났다**는 점이다. 과적합 없이 학습됐다는 뜻이고, 누수 방지를 위해 인코딩을 Pipeline 안에 넣은 선택이 옳았다는 근거이기도 하다. 만약 인코딩을 밖에서 미리 했다면 CV 점수만 높게 나오고 Test에서 무너졌을 것이다.

반대로 아쉬웠던 건 **모델을 아무리 튜닝해도 현금 예측이 개선되지 않았다**는 것이다. 처음에는 하이퍼파라미터를 더 탐색하면 나아질 줄 알았는데, 통계 검정 결과를 보고 나서야 원인이 모델이 아니라 데이터에 있다는 걸 알았다 — 지금 피처로는 카드와 현금을 가를 신호 자체가 없었다. **성능이 안 오를 때 모델부터 의심할 게 아니라 데이터를 먼저 봐야 한다**는 걸 배웠다.

## 개선하고 싶은 부분 (초안)

- **Optuna가 trial을 공평하게 나누지 않는다.** 성적이 좋은 모델에 기회를 몰아주는 방식이라 xgboost가 78회, 나머지는 11회씩만 받았다. "1등을 뽑는" 목적에는 효율적이지만 "모델을 비교하는" 보고서로는 공정하지 않다. 모델별로 별도 study를 돌려 같은 횟수를 보장하는 편이 비교에는 맞다.
- **class weight 트레이드오프를 더 조율하고 싶다.** `balanced`를 넣어 현금 recall 0.50을 얻었지만 precision이 0.19로 떨어졌다. 가중치 자체를 탐색 대상에 넣거나, 재학습 없이 예측 임계값만 조정해 균형점을 찾아볼 수 있다.
- **학습 결과를 보고서 입력까지 자동으로 넘기지 못했다.** `results.csv`까지는 코드가 쓰지만 보고서용 JSON은 사람이 채운다. 평가 함수가 클래스별 지표를 반환하게 고치면 연결할 수 있다.
- **`print` 대신 `logging`을 썼어야 했다.** 단계 태그를 붙여 출력하고는 있지만 레벨과 시각이 남지 않는다.
